# Clear Read verification — 17 October 2026

## Changes

- Added independent Arabic, English and French welcome/goodbye and recognition
  milestone language selection in Preferences > Accessibility. Windows language
  is the default; OCR language remains independently selectable.
- Welcome and goodbye now also use the accessible status live region. Localized
  milestones participate in fallback screen-reader announcements. The status
  element exposes the selected pronunciation language to UI Automation.
- Recognized Arabic text sets the editor direction and pronunciation language;
  subsequent Latin documents restore left-to-right reading.
- Localized open-first and unsaved-text prompt bodies. Windows supplies the
  native dialog button language. Menus, detailed progress and help remain English.
- Corrected the README executable and settings migration information.
- Fixed CI to prepare OCR dependencies before tests and package a complete runtime.

## Evidence

The unchanged baseline passed all 83 functional checks on this machine, including
English/French/Arabic and mixed-language synthetic OCR, hybrid and rotated PDFs,
Unicode exports, unsaved-text detection, status metadata, keyboard-trap checks,
settings migration and credential protection. Final validation passed all 119 checks after the dependency fix. The full output
is in artifacts/verification-2026-10-17.txt.

Synthetic scans do not establish real-world OCR accuracy. UI Automation properties
and automated checks do not establish how a screen reader actually speaks.
No universal accessibility certification is claimed. Live screen-reader listening,
high contrast/200% scaling, representative real scans, clean-machine installation,
dependency redistribution review and signing remain release gates.

## 0.11.3 follow-up

A repeated live launch attempt failed in the computer-use service: its
accessibility window-opened handler did not become ready. The service listed no
Clear Read window afterward. This does not establish an application crash.
The user was asked to open the published app manually for live inspection.

Code inspection found that Accessible Reading Mode previously saved a setting
without changing the editor. It now uses at least 18-DIP document text and added
padding. Screen-reader and contrast options previously appeared to toggle support
without changing behavior; the UI now identifies them as always-on/automatic.
The main menu wraps at narrow widths, main/review minimum sizes are reduced,
checkbox text wraps, and Find/Replace supports resizing and vertical scrolling.
All 123 automated checks passed after these changes. The self-contained 0.11.3
build succeeded with zero warnings/errors, and its Inno Setup installer compiled.

## 0.11.4 editing, menu navigation and startup — final checks

- Added Cut, Copy, Paste and Select All to Edit. Undo/Redo and all new commands
  explicitly target the recognized-document editor; standard Ctrl shortcuts work.

  Tab stays in the menu; Escape and F10 provide alternative menu exit actions.

  Disabling welcome skips the delay; startup sound remains independently optional.
